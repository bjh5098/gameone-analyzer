# gameone_analyzer

한양대학교 D-Dogs OB의 gameone.kr 박스스코어 데이터를 상황별(아웃카운트·주자상황 등)로
필터링해 타자/투수 스탯을 뽑아보기 위한 개인 분석 도구.

## 하고 싶은 것

"이런 상황에서 이 팀/선수 스탯이 어땠는지" 를 조건으로 조회하는 것.
엑셀의 필터 개념과 동일 — 조건을 정의하면 그 조건에 맞는 타석만 모아서 집계한다.

예: "2사 2·3루, 살곶이+배재고 구장 경기만" 조건으로 타율/안타 등을 뽑는 식.

## 페이지 구성 (feature 정의)

**타자 관점 페이지**와 **투수 관점 페이지** 2개로 구성된다. 둘은 별개 페이지이지만
아래 필터 조건은 완전히 동일한 구조를 공유한다 — 차이는 집계되는 스탯 종류뿐
(타자: 타율/안타/타점 등, 투수: 피안타율/자책점 등).

### 필터 조건 (타자·투수 페이지 공통, 확정)

1. **아웃카운트**: 무사(0사) / 1사 / 2사
2. **주자상황** (8가지):
   - 주자없음
   - 1루
   - 2루
   - 3루
   - 1·2루
   - 1·3루
   - 2·3루
   - 1·2·3루(만루)
   - 이 중 **득점권**은 2루 또는 3루에 주자가 있는 경우(2루, 3루, 1·2루, 1·3루, 2·3루, 만루) — 클러치 상황과 동일하게 취급
3. **구장 그룹핑**: 개별 구장 단독 조회(예: 살곶이만) 뿐 아니라 여러 구장을 하나로 묶어 합산 조회(예: 살곶이+배재고) 가능해야 함
4. **연도**: 시즌 단위(2024/2025/2026) 단독 조회 및 여러 시즌 합산 조회
5. **리그**: 리그명(예: 일요 싱글, 일요메이져, 일요리그(C조), 수요 야간 등) 단독 조회 및 여러 리그 합산 조회
   - 구장 그룹핑(3번)과 별개 축 — 같은 리그라도 구장이 다를 수 있고, 같은 구장에서 다른 리그 경기가 열릴 수 있음

### 확장 조건 (가능하면 추가)

6. **점수차**: 1점차 / 2점차 / 3점차 / 4점차 이상
   - 타석 시점 기준 점수차인지, 동점 상황을 별도 항목으로 둘지는 미확정 → [확인 필요]

## 데이터 소스

- 대상 URL 목록: [`games.md`](./games.md) — club_idx=31993 (한양대 D-Dogs OB) 2024~2026시즌 박스스코어
- 경기별 메타데이터(연도/날짜/리그/구장/상대팀/스코어): [`games_meta.csv`](./games_meta.csv)
- 각 URL은 서버사이드 렌더링 HTML이며, 이닝별 타석 이벤트 코드(안타/볼넷/삼진/병살 등)를 파싱해
  아웃카운트·주자상황을 순서대로 시뮬레이션해 재구성함 (사이트가 득점권 여부를 직접 제공하지 않음)

## 진행 상태

95경기(2024~2026시즌) 전부 수집·파싱·SQLite DB 빌드 완료. 타자/투수 분석 페이지가
GitHub Pages로 배포되어 있고, 배포 후 사용자 피드백을 반영해 다음 기능을 추가함:

- 선수별/투수별 스탯 테이블 컬럼 헤더 클릭 정렬(오름차순/내림차순, ▲/▼ 표시)
- OPS·피OPS, 삼진율(K%) 컬럼 추가
- 최소 PA/BF 입력 필터(허수 데이터 방지 — 이 값 이상인 선수/투수만 표시)
- gameone.kr 공식 랭킹 페이지(타자/투수) 컬럼을 참고해 추가 스탯 반영: 타자
  1루타·루타(TB)·희타·희비·고의4구·병살·장타율·BB/K·장타/안타, 투수
  희타·희비·고의4구·폭투·보크. 컬럼 순서도 랭킹 페이지 순서에 맞춤.
  득점/타점/도루/방어율/이닝/WHIP처럼 특정 선수에게 정확히 귀속시킬 수 없거나
  상황별 타석 필터와 개념이 안 맞는 항목(경기 단위 집계라 부분 필터링 시 의미가
  달라짐)은 의도적으로 제외 — 실제로 득점(R) 시뮬레이션 합계를 스코어보드와
  대조해보면 팀 합계 기준으로도 약 21% 과소집계됨(569 vs 721, 95경기 기준)을
  확인해 정확도가 보장되지 않는 스탯은 넣지 않기로 함.
- 리그 필터 체크박스를 "일요성동3부", "수요성동4부"처럼 요일+구장별칭+부수 조합으로
  표시(부수가 확인되지 않은 리그는 원래 이름 유지, 대회성 리그는 "(대회)"로 별도 표시).
  시즌에 따라 이름이 바뀐 동일 리그(예: 생활체육서울시민리그/서울시민리그(S-리그))는
  체크박스 하나로 병합
- 야구 스탯 사이트 느낌의 UI 리디자인(네이비/그린 테마, 카드형 필터 패널)

상세 진행 계획과 파싱 로직(의사코드), 이벤트 코드 사전, 리그별 구장/부수 매핑은
[`CLAUDE.md`](./CLAUDE.md) 참고, 구현 계획 전체는
[`docs/superpowers/plans/2026-08-10-gameone-analyzer.md`](./docs/superpowers/plans/2026-08-10-gameone-analyzer.md) 참고.

## 실행 방법

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/fetch_all.py       # 원문 HTML 캐싱 (최초 1회, 요청당 3초 지연)
.venv/bin/python scripts/build_db.py        # SQLite DB 빌드 + 스코어보드 검증
.venv/bin/python scripts/build_site_data.py # 정적 JSON 생성 (docs/data_batter.json, docs/data_pitcher.json)
```

테스트:

```bash
.venv/bin/python -m pytest tests/ -v
for f in tests/js/*.mjs; do node "$f"; done
```

프론트엔드 로컬 확인:

```bash
cd docs && python3 -m http.server 8123
# 브라우저에서 http://localhost:8123/index.html 등 접속
```

## 알려진 한계

- 콤마(`,`)로 묶인 이벤트는 한 타석 내 이벤트 시퀀스, 슬래시(`/`)는 같은 이닝에서 타순이
  한 바퀴 돌아 동일 타순이 재차 타석에 선 것을 의미함(다른 타석). 이 구분자를 활용해
  이닝별 재구성 정확도를 크게 개선했으나(스코어보드 대조 검증 시 대부분 이닝 일치), 야수
  실책/야수선택 뒤 정확한 진루 베이스 수는 코드만으로 완전히 결정되지 않는 케이스가 있어
  일부 이닝에서 여전히 오차가 남아있음(CLAUDE.md에 known limitation으로 기록).
- 투수 등판 이닝은 투수기록 테이블의 누적 이닝 표기(예: `2 ⅓`)를 순서대로 정수 이닝에
  배정한 근사치이며, 이닝 중간 교체 시점의 타석 단위 정교화는 하지 않음.
- 일부 경기(콜드승 등)는 gameone.kr 소스 데이터 자체에 상대팀 타자기록이 비어있음(파싱
  버그 아님) — 우리팀(D-Dogs OB) 데이터에는 영향 없음.
- 투수 분석 페이지는 한양대학교 D-Dogs OB 투수만 다루며, 상대팀 투수 분석은 범위 밖.
- 점수차 필터는 아직 구현하지 않음(요구사항 미확정).
- 리그 필터의 부수(N부) 및 구장별칭 표기는 사용자가 확인해준 리그에 한해서만 적용됨
  (`docs/js/league-label.js`의 `LEAGUE_TAGS`/`CONFIRMED_CHECKBOX_LABELS` 참고). 원외리그·
  생활체육서울시민리그·서울시민리그(S-리그)·디비전 6-강남구는 부수가 아직 미확인이라
  원래 이름을 그대로 표시함 — 확인되면 해당 테이블에 추가하면 됨.
